1. Operator and contact

2. Data the bot processes

Depending on enabled features, CommunityBot may process:

  • Discord user IDs, server IDs, channel IDs, and role IDs needed to identify commands, configure a server, or assign an approved self-role.
  • XP totals, level information, and activity counters used for ranks and leaderboards.
  • Moderation records, including warning reasons, moderator IDs, and timestamps. Reasons entered by moderators may become part of a member’s warning history.
  • Server configuration, including welcome and log channel choices, feature toggles, approved self-assignable roles, and custom command responses.
  • Operational logs, including startup events, command errors, and diagnostic details.
  • If AI is enabled, the text of prompts sent with the AI command.

The bot is designed not to store ordinary message bodies for XP or message-rate monitoring. Moderators may choose to enter text as a moderation reason or custom response, and those fields can be stored. Discord itself processes data under its own privacy policy.

3. How data is used

Data is used to run commands, save server configuration, maintain warning histories, calculate ranks, assign approved roles, send configured welcome or log messages, troubleshoot errors, and provide optional AI replies. Data is not sold by the bot software.

4. Where data is stored and shared

In the standard self-hosted setup, the database and logs are stored in the bot operator’s configured data directory on the machine or hosting service running the bot. Anyone who administers that machine or has access to those files may be able to access the data. The bot communicates with Discord to provide its features.

AI is disabled by default. If enabled, prompts are sent to the configured Ollama endpoint. The default endpoint is local to the bot machine; if the operator configures a remote endpoint, that endpoint’s operator may receive and process the prompts under their own terms. Do not submit secrets or sensitive personal information to the AI command.

The operator should update this policy if hosting changes, integrations are added, or other third-party services are used.

5. Retention and deletion

Data remains in the bot’s SQLite database and log files until it is deleted, overwritten, or removed under the operator’s retention practices. Warning history can be cleared using the bot’s authorized command. Other records may require the operator to perform a database maintenance action. To request access or deletion, contact [PUBLIC CONTACT EMAIL OR SUPPORT SERVER LINK] and identify the server and relevant user ID; do not send passwords or authentication tokens.

When the bot is permanently discontinued, the operator should remove stored databases and logs unless retention is required by law.

6. Security

The bot token and database should be kept private, access to the host should be restricted, and backups should be protected. No software or transmission method can be guaranteed to be perfectly secure. If a token is exposed, the operator should reset it promptly in the Discord Developer Portal.

7. Children’s privacy

The bot is intended to be used within Discord and is subject to Discord’s age requirements and rules. Do not use the bot to collect sensitive personal information from members.

8. Changes

This policy may be updated when features, hosting, or data handling change. The latest version should remain available at the public URL entered in the Discord Developer Portal.
